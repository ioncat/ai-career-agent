- **Bug fix — vacancy could get permanently stuck as "Failed to load JD: Exception: JD not found", refresh never recovers it.** Follow-up to the transient-race fix below, found on vacancy #106 (a full day old, still broken). Root cause is different: `tools/cv_fetch_jd.py`'s fresh-URL insert never passed `status=` to `insert_vacancy()`, so it silently took the schema default `'fetched'` the instant the row was created — before `markdown_path` was written. A row that fails anywhere in this sequence now lands on `'fetching'`, which the existing recovery mechanisms already know how to retry/reset. 6 new regression tests in `tests/test_cv_fetch_jd.py` (insert uses `status="fetching"`, explicit `fetched` transition, markdown_path-before-dedup ordering, dedup failure doesn't block the `fetched` transition). #106 itself repaired by resetting to `'queued'` (DB backed up first: `agent.db.20260811_133828_pre_v106_stuck_fetch_fix.bak`) — `RSSWatcher` picked it up and completed the fetch within one poll cycle, confirmed live (`status='fetched'`, real `markdown_path`, clean parsed title).

## 2026-07-29

- **Bug fix — long JD titles could truncate onto a trailing space, breaking JD.md write with "No such file or directory".** `_safe_folder_name()` (`tools/cv_fetch_jd.py`) stripped trailing dots/spaces *before* truncating to 80 chars, not after — so a title whose 80th character happened to fall on a space (common with long titles, especially bilingual/Cyrillic ones with commas and parentheticals) produced a folder name ending in a space. Windows silently drops a trailing space when `Path.mkdir()` creates the directory, but the in-memory `Path` object used for the subsequent `jd_path.write_text()` still had the space — the two no longer pointed at the same directory, so the write failed with `[Errno 2] No such file or directory`. Found on vacancy #889 ("Product Owner (сервіси обліку та інтеграції, партнерські сервіси клієнтам …"), via `RSSWatcher: fetch failed` in `logs/bot.log`. Same underlying class as the already-tracked "empty/malformed company leaves trailing separator" bug (see BACKLOG bugs), different trigger. Fix: strip trailing `. `/space both before **and after** the `[:80]` slice. 4 new tests in `tests/test_cv_fetch_jd.py` (forbidden-char strip, trailing-dot strip, empty fallback, and the truncation-lands-on-space regression itself). 893 tests total.
