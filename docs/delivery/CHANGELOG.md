## 2026-10-08

- **Fix (prompts) — discovery stories no longer belong in the CV, Summary included.** The comparison of the two #1693 CVs showed the app's Phase 3 putting a customer-discovery story from the profile ("the team assumed X, the dialogue showed Y") into both the Summary and the role text, while the chat flow had phrased it as a general practice. Rule 23 of `prompts/pm/phase3_cv_draft.md` ("CV describes practice, NOT cases") already existed but named only role descriptions and gave one micro-incident example. It now covers the Summary, names stories of a finding or a surprise as a class, states that they stay out even when the profile holds them, and gives a test (a sentence that can be told as a story with a turning point, or as a single event, is a case) instead of new examples; the first draft of the fix had added examples rewritten from the candidate's own profile story and they were removed. The profile is unchanged (the fact is still needed for interview preparation). Prompt guard tests pass; the full review checklist run is pending.

- **Refactor (prompts, profile) — title terms moved out of the PdM Phase 3 prompt into the user's profile; engine default is the profile (rule zero).** Rule 24b of `phase3_cv_draft.md` no longer encodes a policy: the headline, the Summary opening term and the Experience titles follow the profile's own title rules, and with no such rules nothing adapts (profile default term and profile titles). The asymmetric Summary-opener block and the "headline always tracks the JD" bullets became generic pointers to rule 24b; rule 2 (never change job titles) now refers to the same rule, which removes the old contradiction between rules 2 and 24b. The owner's own rules are in his profile's Generation Rules ("Title terms"): headline and Summary follow the vacancy, Experience titles stay as in the profile unless he asks, one pre-generation question in chat (default: as in the profile), no question in unattended runs and the app, a role marked fixed keeps its title. The known-overlap baseline in `test_prompts_no_profile_overlap.py` is empty again. Open: no chat-flow mechanism yet asks questions that a profile requests (BACKLOG, user-configurable personal rules). An independent checklist review of this change (rule 23 and the title rules) found no blocker and 7 remarks, all fixed the same day: rule 24b names its sources (the profile's "Headline (CV short)" line for the default term, section "Title terms" for the rules); rule 24 takes its term from 24b instead of hardwiring one; the archetype-term exception for the headline is stated as independent of the profile's title rules; rule 23 now excludes Key results, requires that "practice" is what the profile supports as regular work (a single event is stated plainly or left out) and wins over the more-specific-block lookup for the AI paragraph. `tests/test_profile_contract.py` gained "Headline (CV short)" as a required section and an optional-section mechanism ("Title terms": may be absent, must not be empty when present, must be named by the engine). Stale comments in `core/cv_metrics.py` reworded.

- **Process (prompts) — three layers that make the "prompts are directives only" rule hard to forget.** The rule already stood in `CLAUDE.md`, and a prompt edit still copied the candidate's own profile story into new examples (caught by the owner, not by a test). (1) `docs/delivery/PROMPT_EDITING_RULES.md`: five rules (no candidate content even reworded, neutral or no examples, no history, personal preferences are not engine rules, say it once) with what enforces each. (2) `scripts/prompt_rules_gate.py`, a Claude Code PreToolUse hook (wired in the local, untracked settings file): the first write to `prompts/`, `skill/SKILL.md` or `.claude/commands/` in a session is blocked once and the rules are printed to the model; the retry passes; shell and Python commands that write to those paths are gated too. (3) `tests/test_prompts_no_profile_overlap.py`: fails when a prompt line repeats 10+ consecutive words found in a local profile or interview-prep file (engine-config sections of the profile are excluded because they hold instructions). Limits: a reworded copy that breaks the word run is not caught; the test is skipped on a clean clone. One accepted baseline overlap is listed in the test (the Summary-opener title policy in the PdM Phase 3 prompt, tied to the open role-title decision in BACKLOG); a stale entry fails the test, so the list only shrinks.
