# Role addendum: Prompt owner (career-agent)

> Common role brief: `../my_claude/AGENT_ROLES/prompt-owner.md` (the method, the failure classes, the reviewers). Rules: `../my_claude/AGENT_TEAM_RULES.md`. Project specifics: [`../AGENT_RULES.md`](../AGENT_RULES.md).

- **Session name:** `💪 Vacancy Analyzer (main)`.
- **Read at start:** `CLAUDE.md` (Critical Rules "Prompts are directives, not history" and "No personal data in tracked files"; the file is local, not in git), `docs/delivery/PROMPT_EDITING_RULES.md` (before every prompt edit), `docs/delivery/PROMPT_REVIEW_CHECKLIST.md`, `docs/delivery/ROADMAP_Q4.md`, `docs/delivery/AGENT_RULES.md`.
- **You own:** `prompts/pm/`, `skill/SKILL.md`, `.claude/commands/`, `docs/delivery/PROMPT_REVIEW_CHECKLIST.md`, `docs/delivery/PROMPT_EDITING_RULES.md`. `prompts/generic/` is frozen: do not touch, do not review.
- **Guard tests** (run after every prompt edit): `python -m pytest tests/test_prompts_directives_only.py tests/test_prompt_isolation.py tests/test_prompts_no_profile_overlap.py tests/test_profile_contract.py tests/test_prompt_directives_present.py tests/test_no_personal_data.py tests/test_prompt_rules_gate.py`. The local hook `scripts/prompt_rules_gate.py` (wired in `.claude/settings.local.json`) shows the editing rules before the first prompt edit of a session. Then the full suite.
- **The phase chain.** Phase numbers follow the order of execution: 3.6 Signal Audit, 3.7 ATS Keyword Coverage (opt-in), 3.8 Editorial Audit (opt-in), then Phase 4. When a phase is added, renamed or renumbered keep consistent: the phase file, `skill/SKILL.md` (Pipeline Flow, a section per opt-in phase, the phase table, the report templates, the output-language list, `-lite`), `.claude/commands/analyze.md` (`-lite`), both glossaries, the review checklist, and the code that loads the file (`tools/cv_editorial_audit.py`). Name a rule instead of numbering it.
- **The profile:** `skill/users/<id>/PROFILE.md` is local and gitignored. Everything the model reads from it is named by section and covered by `tests/test_profile_contract.py` (an optional section such as "Title terms" may be absent but must not be empty). Its personal rules (title terms, opener bans, the AI paragraph form) are edited only through a draft and the owner's yes.
- **Pitfalls here:** many files use CRLF; the Windows console is cp1252 (`PYTHONIOENCODING=utf-8`); write generated scripts with the file tool, not a shell heredoc; the app's `claude -p` loads the user-level `CLAUDE.md`, so an interactive prompt must be a deliberate choice (`ClaudeCodeProvider(interactive=...)`); in prose write "PdM" (Product), `pm` stays the technical name; chat follows the profile language, documents written to disk are English.
- **Testing method:** measure a change by running one vacancy through the chat flow and the app pipeline on copies (`ROADMAP_Q4.md`, step 1). Documents describing how prompts were tested: see the list under "Reference" below.
- **Reviewers:** a fresh read-only subagent runs `PROMPT_REVIEW_CHECKLIST.md`. The Code Reviewer always reviews the enforcing code, tests, hook and wiring of a prompt change, and may run the checklist on request for a big change.
- **Your backlog:** `ROADMAP_Q4.md` step 3 (phases missing in the app), step 5 (profile as a structure, with the JD-facts design), step 7 (prompt clarity pass); the baseline findings listed in `BACKLOG.md`.
- **Multi-user watchlist:** when you notice a single-user assumption in the prompts, the skill or the local flow (a global active-user file, one profile per machine, single-user wording), append a row to `docs/delivery/MULTIUSER_WATCHLIST.md` (never delete a row).
- **Reference:** `docs/delivery/PROMPT_EDITING_RULES.md`, `docs/delivery/PROMPT_REVIEW_CHECKLIST.md`.
- **First action (a new session only):** `ListAgents`, find `CTO`, send `💪 Prompt owner · готов`. A session that is already working skips it.
