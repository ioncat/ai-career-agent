EPIC-21 — Pipeline Control Architecture

How the deterministic skeleton and the cognitive model relate. Companion to docs/delivery/Epics/EPIC-21-deterministic-vs-cognitive-pipeline.md.

Control principle. The FSM is primary — it owns the control flow and all I/O. The LLM is a subordinate pure function: text-in → structured JSON judgment-out, with no access to the filesystem, the DB, or the decision of "what runs next". Cognitive output influences branching (data-dependent guards) but never executes a transition. Code runs the model — not the model the code.

Local-mode caveat: in Claude Code the agent is an unavoidable outer trigger (reasoning floor cannot be zeroed). The goal (Task 6) is to make that agent a thin trigger that delegates to the FSM — not an orchestrator.
Cognitive state — FSM invokes the LLM here Deterministic control / compute — pure FSM (Python) Interactive pause-state — FSM awaits the user

Guards in […] are pure FSM if checks on the JSON the LLM returned. Every phase state has a cognitive core (LLM call) wrapped in deterministic Python steps. P2.5 is the only multi-turn state — it pauses for the user and is skipped in batch / headless contexts.

View 2 — Sequence (control inversion · who calls whom)

sequenceDiagram
    actor U as User
    participant FSM as FSM (orchestrator)
    participant LLM as LLM (cognitive fn)
    participant SVC as Services · PDF / DB / FS

    U->>FSM: /analyze  (trigger only)
    activate FSM
    FSM->>LLM: P1+2 prompt (+ JSON schema)
    LLM-->>FSM: JSON {analysis, VScore dims, fit, barriers}
    FSM->>FSM: compute VScore + recommendation (deterministic)
    FSM->>SVC: save JD_analysis.md · DB write
    FSM-->>U: Quick Scan

    opt barriers ≠ none  (interactive pause)
        FSM-->>U: present barriers
        U->>FSM: response
        FSM->>LLM: classify resolved / gap
        LLM-->>FSM: classification
        FSM->>SVC: persist PROFILE.md · JD_analysis.md
    end

    FSM-->>U: «Генерируем CV?»
    U->>FSM: yes
    FSM->>FSM: precompute metrics (Top-15 · tools · repetition)
    FSM->>LLM: P3+3.5 prompt (+ metrics)
    LLM-->>FSM: JSON {cv_md, review}
    FSM->>SVC: weasyprint PDF · save · DB
    FSM-->>U: review + CV · «cover?»
    U->>FSM: yes
    FSM->>LLM: P4 prompt
    LLM-->>FSM: JSON {cover_md}
    FSM->>SVC: save · DB
    deactivate FSM

Every solid arrow into LLM and SVC originates from FSM. The LLM only ever responds (dashed returns) — it initiates nothing. The User is an external actor the FSM awaits, not a controller.
